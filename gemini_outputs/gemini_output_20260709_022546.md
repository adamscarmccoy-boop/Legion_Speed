Given the complexity of your **Legion/Sovereign** architecture, you likely have multiple paths, virtual environments, and potentially conflicting global installations. On Windows, `npm` and `npx` issues usually stem from one of three things: **Path pollution**, **Corrupted Cache/Global folders**, or **Version Mismatches**.

Since you are already using Python `.venv` logic to isolate your vision pipeline, you should apply the same "Isolation Principle" to Node.js.

Here is the systematic recovery procedure.

---

### Phase 1: The Diagnostic (Run this first)
Open **PowerShell as Administrator** and run this block to see exactly where the system is looking for Node.

```powershell
Write-Host "--- NODE DIAGNOSTIC ---" -ForegroundColor Cyan
Write-Host "Node Version: " -NoNewline; node -v
Write-Host "NPM Version:  " -NoNewline; npm -v
Write-Host "NPX Version:  " -NoNewline; npx -v
Write-Host "`n--- PATH RESOLUTION ---" -ForegroundColor Cyan
where.exe node
where.exe npm
where.exe npx
Write-Host "`n--- NPM GLOBAL CONFIG ---" -ForegroundColor Cyan
npm config get prefix
```

**If `where.exe` returns multiple paths** (e.g., one in `Program Files` and one in `AppData`), you have a path conflict.

---

### Phase 2: The Three Recovery Paths

#### Path A: The "Surgical Fix" (Fixing the PATH)
If the commands are "not recognized," your Environment Variables are broken.

1.  Press `Win + R`, type `sysdm.cpl`, hit Enter.
2.  Go to **Advanced** $\rightarrow$ **Environment Variables**.
3.  Under **System Variables**, find **Path** and click **Edit**.
4.  Ensure these two exist. If not, add them:
    *   `C:\Program Files\nodejs\`
    *   `%AppData%\npm` (This is where `npx` and global binaries live)
5.  **Move them to the TOP** of the list to ensure they override any ghost installations.
6.  **RESTART your terminal/IDE.**

#### Path B: The "Nuclear Option" (Clearing Corrupted Cache)
If `npm` works but `npx` fails or gives "EACCES" / "permission denied" errors, your global `AppData` is likely corrupted. This is the most common "fix" for professional developers.

**Run this in PowerShell (Admin):**
```powershell
# 1. Force clear the cache
npm cache clean --force

# 2. Delete the global npm and npx folders (The "Nuke")
# WARNING: This removes globally installed packages (like nodemon, etc.)
# You will need to re-install them with 'npm install -g <package>'
Remove-Item -Recurse -Force "$env:AppData\npm" -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "$env:AppData\npm-cache" -ErrorAction SilentlyContinue

# 3. Verify
npm -v
```

#### Path C: The "Architect's Solution" (NVM-Windows)
**Highly Recommended.** Since you use `.venv` for Python to prevent library hell, you should use **NVM (Node Version Manager)** for Node. This prevents you from ever having to "fix" the system path again because NVM manages the symlinks.

1.  **Uninstall** all existing versions of Node.js via "Add or Remove Programs."
2.  **Delete** `C:\Program Files\nodejs`.
3.  **Delete** `%AppData%\npm` and `%AppData%\npm-cache`.
4.  Download and install **[nvm-windows](https://github.com/coreybutler/nvm-windows/releases)** (Download `nvm-setup.exe`).
5.  Open a **new** PowerShell (Admin) and run:
    ```powershell
    nvm install latest      # Install the newest version
    nvm use latest          # Switch to it
    nvm alias default latest # Set it as the system default
    ```
6.  Verify: `node -v` and `npm -v` should now work perfectly.

---

### Phase 3: Integration with your Pipeline

To ensure your `mcp_api_server.py` or any web-based tools in the **Legion** ecosystem don't break when you update Node, follow these rules:

1.  **Never use global installs for project dependencies.**
    *   ❌ `npm install -g some-package`
    *   ✅ `npm install some-package` (inside your `C:\WEB CASE STUDY` folder)
2.  **Use `npx` only for one-off executions.**
    *   If you need a tool like `tsc` (TypeScript) or `prisma`, use `npx tsc` so it pulls the version local to your project rather than relying on the system's global (and potentially broken) environment.
3.  **Check your `.env` files.**
    *   If any of your Python scripts call `subprocess.run(["npm", ...])`, ensure they are being called from a shell that has been restarted after your NVM/Path changes.

**Summary for your Manifest:**
*   **Node Environment Manager:** NVM-Windows.
*   **Global Path:** `%AppData%\npm`.
*   **Strategy:** Local-first dependency management (to mirror your Python `.venv` architecture).
