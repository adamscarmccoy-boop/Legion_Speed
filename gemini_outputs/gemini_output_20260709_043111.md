To integrate a lightweight LLM like **Gemma-2b** into your **Sovereign/Legion** architecture as an ONNX runtime engine, you cannot simply "save as" from Transformers. You must use the **Hugging Face Optimum** library, which is the industry standard for graph-optimizing Transformers into the ONNX format.

This script will:
1.  **Download** the raw weights from Hugging Face to a specific **Hard Path** on your drive.
2.  **Compile** them into a highly optimized ONNX graph (including KV-caching for speed).
3.  **Verify** the output is ready for your orchestration engine.

### 🛠️ Prerequisites
You must install these specific libraries in your `C:\STUDIES_BACKUP\.venv_fresh` (or your preferred venv):

```powershell
pip install torch transformers accelerate huggingface_hub optimum[exporters] onnxruntime
```

### 🧬 The Compiler Script: `gemma_onnx_forge.py`

```python
import os
import torch
from huggingface_hub import snapshot_download
from optimum.exporters.onnx import main_export
from pathlib import Path

# ─── HARD PATH CONFIGURATION ───
# This is where the raw weights will live (The "Source of Truth")
RAW_WEIGHTS_DIR = r"C:\WEB CASE STUDY\models\gemma_raw"

# This is where the compiled ONNX engine will live (The "Production Brain")
ONNX_EXPORT_DIR = r"C:\WEB CASE STUDY\models\gemma_onnx"

# The model ID on Hugging Face
# 'google/gemma-2b' is the small version. 
# Note: You may need to run 'huggingface-cli login' if the model is gated.
MODEL_ID = "google/gemma-2b"

def forge_onnx_model():
    """
    Downloads raw weights and compiles them into an optimized ONNX graph.
    """
    print(f"🚀 [FORGE] Starting Gemma ONNX Pipeline...")
    print(f"📂 Target Raw Path: {RAW_WEIGHTS_DIR}")
    print(f"📂 Target ONNX Path: {ONNX_EXPORT_DIR}")

    # 1. Ensure directories exist
    os.makedirs(RAW_WEIGHTS_DIR, exist_ok=True)
    os.makedirs(ONNX_EXPORT_DIR, exist_ok=True)

    # 2. DOWNLOAD PHASE
    if not os.path.exists(os.path.join(RAW_WEIGHTS_DIR, "config.json")):
        print(f"📥 [DOWNLOAD] Downloading {MODEL_ID} to hard path...")
        snapshot_download(
            repo_id=MODEL_ID,
            local_dir=RAW_WEIGHTS_DIR,
            local_dir_use_symlinks=False,
            ignore_patterns=["*.msgpack", "*.h5"] # Skip unnecessary formats
        )
        print(f"✅ [DOWNLOAD] Weights secured at {RAW_WEIGHTS_DIR}")
    else:
        print(f"ℹ️ [SKIP] Raw weights already exist at {RAW_WEIGHTS_DIR}")

    # 3. COMPILER PHASE (Optimizing for Inference)
    print(f"⚙️ [COMPILE] Compiling to ONNX (this may take several minutes)...")
    print(f"📝 Task: text-generation-with-past (Optimized for KV-Caching)")
    
    try:
        # main_export handles the heavy lifting: 
        # - Converts weights to ONNX
        # - Optimizes the computation graph
        # - Generates the required configuration files
        main_export(
            model_name_or_path=RAW_WEIGHTS_DIR,
            output=ONNX_EXPORT_DIR,
            task="text-generation-with-past", # Crucial for speed (enables KV cache)
            device="cpu",                     # Compile on CPU to avoid VRAM spikes during export
        )
        print(f"✅ [COMPILE] SUCCESS! ONNX engine built at {ONNX_EXPORT_DIR}")
        
    except Exception as e:
        print(f"❌ [COMPILE] FAILED: {str(e)}")
        return

    # 4. VERIFICATION
    print("\n" + "="*30)
    print("📊 FINAL DIRECTORY INSPECTION")
    print("="*30)
    for file in os.listdir(ONNX_EXPORT_DIR):
        print(f"  📄 {file}")
    print("="*30)
    print(f"🚀 Ready for Sovereign Orchestration.")

if __name__ == "__main__":
    # Check for HF Token if model is gated
    # If you haven't logged in, this might fail for Gemma.
    # Run 'huggingface-cli login' in your terminal first.
    forge_onnx_model()
```

### 🧠 How to use this in your "Sovereign" Orchestrator

Once the script above finishes, you don't use `transformers` to run the model anymore. You use `Optimum`'s `ORTModelForCausalLM`. This is significantly faster and uses much less RAM.

Here is the snippet you should add to your **`sovereign_intelligence.py`** or a new **`onnx_inference_engine.py`**:

```python
from optimum.onnxruntime import ORTModelForCausalLM
from transformers import AutoTokenizer

class SovereignONNXBrain:
    def __init__(self, model_path: str):
        self.model_path = model_path
        print(f"🧠 [BRAIN] Loading ONNX Engine from {model_path}...")
        
        # Load the optimized ONNX model
        self.model = ORTModelForCausalLM.from_pretrained(model_path, provider="CPUExecutionProvider")
        self.tokenizer = AutoTokenizer.from_pretrained(model_path)

    def think(self, prompt: str, max_new_tokens: int = 128):
        """Runs high-speed inference via ONNX Runtime."""
        inputs = self.tokenizer(prompt, return_tensors="pt")
        
        # Generate using the optimized ONNX graph
        outputs = self.model.generate(
            **inputs, 
            max_new_tokens=max_new_tokens,
            do_sample=True,
            temperature=0.7
        )
        
        return self.tokenizer.decode(outputs[0], skip_special_tokens=True)

# --- TEST RUN ---
if __name__ == "__main__":
    BRAIN_PATH = r"C:\WEB CASE STUDY\models\gemma_onnx"
    brain = SovereignONNXBrain(BRAIN_PATH)
    
    response = brain.think("System Status: Analyze the connection between audio RMS energy and visual chromatic aberration.")
    print(f"\n🤖 GEMMA-ONNX RESPONSE:\n{response}")
```

### 🗝️ Key Technical Details for your Manifest:

1.  **The "Task" Parameter (`text-generation-with-past`)**: This is the most important part of the compilation. It tells the compiler to create separate ONNX nodes for the "Past Key Values" (KV Cache). Without this, the LLM has to re-calculate the entire sentence every time it generates a new word, making it 10x slower.
2.  **Hard Path Integrity**: By using `snapshot_download` with `local_dir`, we ensure that even if you go offline, your **Legion** system has a local "Library" of weights that doesn't rely on Hugging Face's cache folder (which is usually hidden in `AppData`).
3.  **Memory Profile**: Gemma-2b in ONNX format will typically run on ~4GB of RAM, making it perfect for your **GTX 1650** / CPU split architecture. The CPU handles the logic, and the GPU handles the vision.
